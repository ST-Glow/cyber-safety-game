# 七年级《互联网应用与创新》卡牌任务适配地图

这份地图定义“共用交互手感”和“课程必须改变的对象”之间的边界。它不是把30课压成一张网络地图，而是让每课都经过同一个短循环：

`观察事件 → 选行动卡 → 选对象与目标 → 看到状态后果 → 检查/修正 → 交付学习证据`

## 六类牌桌

| 课程 | 牌桌对象 | 可见行动 | 完成证据 |
| --- | --- | --- | --- |
| 1–3 | 发展阶段、创新事件、生活影响 | 排序、连接、比较、选证据 | 时间线、影响链、创新理由 |
| 4–10 | 数据包、节点、协议、地址、路由、端口 | 分包、转发、改道、寻址、路由、重传、配置 | 路径、节点状态、协议选择、网络结果 |
| 11–15 | 服务请求、域名、搜索结果、实验记录 | 请求、解析、搜索、观察、对比、追踪 | 实验记录、搜索策略、路径解释 |
| 16–20 | HTML 元素、CSS 样式、Markdown、页面和链接 | 设为标题、调整层级、添加样式、预览、链接、发布 | 可运行网页、代码片段、页面结构 |
| 21–26 | 设备、服务场景、素材、作品和发布渠道 | 选择场景、比较方案、组合资源、规划发布、评估风险 | 方案、作品草稿、发布决策 |
| 27–30 | 个人信息、受众、来源、版权证据、内容风险 | 遮挡、移除、缩小受众、替换、核验、暂不分享、说明理由 | 风险判断、保护措施、证据和倡议 |

## 适配器必须提供

- 课程事件、角色身份和任务目标。
- 可操作对象及其状态字段。
- 行动卡、合法目标、错误原因和修正建议。
- 行动后果和可视化所需的状态变化。
- 部分完成、失败、成功和交付条件。
- 学生可以带走或复述的学习证据。
- 结算后的一个或两个反思问题。

## 不能只换文字的课程

- 第17课必须生成真实 HTML 产物，不能只显示“答对了标签”。
- 第19课必须体现分工、冲突或协同结果，单人牌桌只能模拟协作协议，不能替代真实协同编辑。
- 第26课必须留下作品草稿或发布决策，不能只选择“短视频”卡牌。
- 第27–30课必须保留理由、证据和不确定性，不能用一个红灯/绿灯代替伦理判断。

## 视觉规则

统一牌框、图标、字体层级和反馈动效；中央牌桌按课程切换：

- 网络课：控制室、节点和线路。
- 网页课：编辑台、代码卡和预览屏。
- 创作课：素材台、剪辑轨道和发布预览。
- 安全课：隐私检查台、风险标签和受众范围。

倒计时只在确有任务压力的课程启用。历史、隐私、版权和伦理课程使用“后果预览”代替强制限时。
