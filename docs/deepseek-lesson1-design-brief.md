# 第1课双班智能体与互动试玩：教材到玩法的完整设计稿

这份文档把第1课的教材目标、游戏流程、视觉方向、智能体规则、数据记录和验收标准整理在一起，供 DeepSeek Harness 做 UI/玩法审查和后续修改。它是结构化设计上下文，不是完整聊天记录；完整聊天包含临时部署操作、浏览器状态和不应交给代理的凭据相关信息。

## 1. 项目定位

项目面向七年级学生，课程主题是“互联网发展与可靠创新”。学生通过校园地图上的网络实验，观察网络结构、通信规则和可靠性设计如何影响消息传递。

游戏要让学生经历“观察 → 提出判断 → 选择行动 → 看结果 → 比较证据 → 形成解释”，而不是点击唯一正确答案。行动卡全部可以尝试，选错只产生反馈，不锁死卡牌，也不直接告诉学生正确卡牌。

第1课的三个核心知识点：

1. **单点故障与中央计算机结构**：多个终端依赖同一个核心设备，核心设备停止后依赖它的网络可能一起中断。
2. **通信协议与标准化**：通信双方要共同遵守规则；标准化让规则不同的网络能够互相理解。
3. **备用路径与冗余连接**：主线路断开后仍有另一条线路可以传递消息，替代路径可以提高网络可靠性。

## 3. 开场体验

首次进入完整游戏先显示欢迎页和可跳过的五步聚光导览：

1. 顶部任务栏：课程、挑战、剩余时间和证据数量。
2. 中央场景：设备、线路、故障点和测试对象。
3. 反馈区：行动结果、错误原因和下一步思考提示。
4. 手牌区：五张行动卡都可以尝试。
5. 代表性行动卡：说明接入、连接、协议、备用路径和测试分别在做什么。

导览使用深蓝黑色半透明遮罩，只让当前区域保持金色描边、柔和发光和轻微脉冲；无关区域明显暗化。说明文字要足够大，适合中学生阅读。提供“上一步”“下一步”“跳过导览”，最后一步为“开始探索”。菜单中可以重新查看导览，重看时暂停主线计时。

首次导览不重复打断重新开始的游戏。Escape 可以关闭导览或跳过当前导览。

## 4. 核心玩法循环

每次操作的基本顺序是：

```text
选择行动卡 → 点击场景对象 → 查看反馈 → 比较操作前后证据
```

五张行动卡：

- **接入设备**：把终端或网络接入场景。
- **建立连接**：连接两个网络节点或线路。
- **配置协议**：让通信双方遵守同一套规则。
- **增设备路**：为关键线路增加备用路径。
- **运行测试**：观察通信结果并记录证据。

五张卡都可以选择。卡牌选择本身不算有效进展；只有成功操作、成功测试或正确完成配对才算进展。错误操作给出具体原因和观察提示，不扣生命、不锁卡、不强迫重开。

主线倒计时在导览和知识匹配期间暂停；普通游戏中的探索和错误反馈仍属于挑战过程。牌框使用与校园地图匹配的米白纸张、木质边缘、校园蓝绿和少量金色，避免蓝色科幻霓虹牌框破坏校园纸牌风格。

## 5. 三个网络挑战

### 挑战一：中央计算机单点故障

学生先把早期终端接入中央计算机，再建立线路，运行一次正常通信测试，然后触发中央设备故障并再次测试。

希望学生记录并比较：

- 故障前通信是否成功。
- 中央设备停止后哪些网络受到影响。
- 为什么一个核心设备会让多个终端同时失去通信。

挑战结束后进入第1次知识匹配。

### 挑战二：通信协议不一致

学生连接两个网络，观察规则 A 与规则 B 不一致时的通信结果，再配置共同协议并重新测试。

希望学生记录并比较：

- 两个网络是否已经物理连接。
- 规则不同为什么仍然不能互相理解。
- 统一规则后通信发生了什么变化。

挑战结束后进入第2次知识匹配。

### 挑战三：备用路径与冗余连接

学生先测试主线路，再模拟主线路故障，接入备用线路，最后重新测试。

希望学生记录并比较：

- 主线路正常时的结果。
- 主线路断开后的结果。
- 增加替代路径后消息是否恢复。

挑战完成后进入第3次知识匹配，匹配关闭后才显示成果展板和上传流程。

## 6. 知识卡牌匹配

每个挑战后显示一次匹配弹层，每次2组概念与解释，共4张卡。卡牌顺序随机，概念卡和解释卡使用不同暖色边框。

匹配内容：

### 第1次

- `单点故障` ↔ `核心设备停止后，依赖它的网络可能一起中断`
- `中央计算机结构` ↔ `多个终端依赖同一个核心设备`

### 第2次

- `通信协议` ↔ `通信双方共同遵守的规则`
- `协议标准化` ↔ `让规则不同的网络能够互相理解`

### 第3次

- `备用路径` ↔ `主线路断开后仍有另一条线路可以传递消息`
- `冗余连接` ↔ `增加替代路径，提高网络可靠性`

交互优先采用拖动：把概念卡拖到解释卡上完成配对。为触屏和键盘保留点击两张卡的后备方式。正确配对后锁定并显示绿色状态；错误配对显示具体解释、短暂砖红色抖动，然后恢复可选。错误、跳过和未完成都不阻塞主线。

提供“跳过本次匹配”和“继续探索”。全部配对完成后等待3秒自动继续，也可以立即点击继续。Escape 等同于跳过当前检查点。匹配弹层内仍可以打开小糖求助，但自动邀请在拖动、错误动画和完成倒计时期间不展示。

## 7. 两种智能体

两组共享同一真实 AI 服务、课程提示档案和回答风格。AI 只围绕观察、比较、证据和下一步验证提问，不公布正确卡牌、正确目标、匹配答案、班级条件或学生姓名。

主动式 `proactive`：

- 一般任务宽限10秒。
- 空闲15秒、无有效进展25秒可产生邀请。
- 匹配题犹豫15秒可产生邀请。
- 当前目标第一次明确出错后，抑制该目标的主动邀请。

反应式 `reactive`：

- 当前目标累计两次有效错误后产生邀请。
- 短时间重复连点去重；重新选择并提交的尝试正常记录。

两组共同规则：

- 每名学生、每个课次、第1课最多展示3次自动邀请。
- 自动邀请之间冷却30秒。
- 手动求助不消耗自动邀请额度。
- 支持面板打开、页面失焦、导览、上传、拖动和错误动画期间暂停或抑制不合适的邀请。
- 帮助打开或目标变化后，迟到的 AI 回复必须丢弃，不能覆盖新目标。
- AI 失败要显示明确失败状态，允许重试或继续，不用预设文字假装真实 AI。

## 8. 录像、JSON和隐私边界

完整游戏和互动试玩都只允许共享当前游戏标签页：静音、不采集摄像头和麦克风。录像优先 MP4，兼容 WebM；目标15fps、1280×720上限、约1.5Mbps。浏览器用 IndexedDB 保存分块，服务器核验录像、操作记录和结果后才显示保存完成。

记录包括：

- 学生自报班级和姓名、实验版本、课次和服务器分组。
- 行动卡选择、场景点击、错误、成功、匹配尝试。
- 智能体触发原因、是否展示、接受/拒绝/稍后处理、AI 请求结果和后续行动。
- `session.jsonl`、`summary.json`、`recording.mp4`或`.webm`、`manifest.json`。

姓名和录像不发送给 AI。私有 OSS 只通过服务器签发的范围票据上传。失败时可以重试或下载本机备份；匿名访问不能读取录像或清单。

## 9. UI审查重点

请 DeepSeek 优先检查这些问题：

### 可读性

- 导览文字、中间反馈文字和匹配说明是否足够大。
- 1024×768 和 1366×768 是否没有滚动、遮挡或按钮超出屏幕。
- 学生是否能一眼区分当前目标、可点击对象、概念卡和解释卡。
- 暗化遮罩是否足够突出目标，但没有让文字失去对比度。

### 视觉统一

- 暖色纸牌框是否与校园地图、设备插画和反馈条统一。
- 选中状态优先使用金色、砖红和米白，减少冷色霓虹。
- 错误、成功、暂停、跳过和上传状态是否有清楚且一致的颜色语义。
- 移动端或触屏拖动时是否有明显的拖拽中、放置成功和放置失败反馈。

### 可玩性

- 是否仍然允许学生试错，而不是一眼看到唯一正确卡牌。
- 错误反馈是否提供思考线索，却没有直接公布答案。
- 三个挑战的观察、比较和反馈是否形成明显递进。
- 匹配题是否像知识整理，而不是固定位置记忆。
- 3秒自动继续是否给学生足够的完成反馈，同时不拖慢节奏。

## 10. 修改边界和验收

DeepSeek 修改时先只读审查，再提出问题清单；确认后才修改。默认只允许修改第1课、共享卡牌模块、相关上传后端和测试。不要改动 Godot 主游戏、第4课牌桌、旧糖果乐园入口、生产 FC、OSS、RAM、域名、环境变量和真实学生数据。

本地验证：

```powershell
npm test --prefix classroom-web
npm test --prefix cloud/aliyun-upload-api
node classroom-web/tools/qa-lesson1-experiment.mjs chrome
node classroom-web/tools/qa-lesson1-experiment.mjs edge
git diff --check
```

审查完成应交付：

1. 按严重程度排列的 UI、玩法、学习目标和数据风险。
2. 每个问题对应的文件路径、复现步骤和建议修改。
3. 修改后的差异和测试结果。
4. 未覆盖的真实机房浏览器、多人并发、网络中断或人工共享选择器风险。
